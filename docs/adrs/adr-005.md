# ADR-005: Local Storage — SQLite vs flat files vs no persistence

## Context
We want local storage to persist historical events for TUI query sessions, metrics tracking, and long-term diagnostic graphing.

## Decision
We chose **SQLite** (via the `rusqlite` crate with `bundled` feature).

## Consequences
- Single on-disk database file with proper indices.
- Simple schemas and transactional durability.
- We restrict DB file permissions to `0600` to prevent unauthorized local reading.
- DB failures are logged and bypassed cleanly, maintaining our core continuous audio invariants (§1.2).
