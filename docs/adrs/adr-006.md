# ADR-006: Process Identity — Raw comm strings vs hashing

## Context
When processes trigger scheduling or lifecycle tracepoints, the kernel exposes the task `comm` name (e.g. `chrome`, `sh`). Forwarding these names in plaintext creates privacy vulnerabilities (e.g. identifying exact web pages or user files being read).

## Decision
We chose **FNV-1a 64-bit hashing** of all process names inside the kernel-space eBPF programs, before they are ever copied to userspace ring buffers.

## Consequences
- Guarantees zero sensitive raw strings are leaked to logs or the OSC output stream.
- Extremely lightweight hashing overhead within eBPF verifier limitations.
- Loss of direct readability; lookup mappings must be explicitly opted-in by the operator for debug workflows.
